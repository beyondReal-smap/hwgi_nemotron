[Summary]
- v2는 진행 가능하지만, P0~P2와 P3~P4는 분리하고 `percentile_score`는 `scipy` 없이 `numpy sort + searchsorted`로 구현하는 안을 권장합니다.

[Findings]
- 쟁점 A: 수정 제안. 100만 행 `argsort` 2회도 단건 분석 20초대 흐름에서는 병목이 아닙니다. 다만 실제 현재 기준은 10만 샘플인지 100만 전체인지 먼저 고정해야 합니다. 전체 rank 배열이 필요 없으면 `np.sort(raw_scores)` 1회 후 상위 hit만 `searchsorted`로 백분위를 계산하면 충분합니다. 동률은 좌우 경계를 평균 내면 `rankdata(method='average')`와 동등하게 처리할 수 있어 `scipy` 의존성은 불필요합니다. 캐싱은 동일 임베딩 재요청이 잦다는 근거가 나오기 전까지 보류합니다.

- 쟁점 B: 합의. B-2가 맞습니다. 메인 raw 점수는 기존 해석과 색상 체계를 유지하고, 보조 라벨로 `상위 0.1%`를 작게 노출합니다. 모바일에서는 두 줄이 한 줄 괄호보다 안전합니다. 비교표에는 `평균 raw 점수`, `평균 상위 백분위`, `lift`를 분리해 넣는 편이 낫습니다. 툴팁 단독 노출은 핵심 해석값을 숨기므로 비추천입니다.

- 쟁점 C: 수정 제안. 품질 게이트는 차단이 아니라 경고 배지가 맞습니다. `p99-p50 < 3`은 보수적 1차값으로 두고, `<5`는 검증 후 상향 후보로 둡니다. `core_lift < 2`는 현재 근거가 약하므로 Plan C에서 정상 케이스의 분포를 먼저 봐야 합니다. `target_size_volatility`는 A/B 비교 전용 플래그로 추가 가치가 있습니다. 단, 일반 단건 분석 품질 플래그와 섞지 말고 비교 화면 전용으로 두는 편이 명확합니다.

- 쟁점 D: 수정 제안. 하한 0.1은 구현 기본값으로 둘 수 있지만 확정값은 아닙니다. 0.05/0.1/0.2를 Plan A에서 비교해 `std`, `p99-p50`, Known-target 통과율, 상위 50명 중 명시 타겟 일치율을 같이 봐야 합니다. 특히 0.05는 분포는 넓히지만 cosine 과의 결합에서 비일치자를 과도하게 밀어낼 수 있습니다.

- 쟁점 E: 수정 제안. 한 PR은 비추천입니다. P0+P1+P2는 읽기 전용 노출 변경으로 묶고, P3+P4는 점수 의미와 품질 판정이 바뀌므로 별도 PR이 안전합니다. P3 적용 후 LLM 리포트 톤, cohort 컷, 기존 백테스트가 같이 흔들릴 수 있어 분리 배포가 맞습니다.

- 추가 발견: `PopulationStats` 확장은 기존 `jsonl` 호환을 반드시 고려해야 합니다. 새 필드는 `None` 또는 기본값 허용이 필요합니다. 또한 `percentile_score` 계산은 반올림 전 raw float 기준으로 해야 동률·표시 불일치를 줄입니다.
