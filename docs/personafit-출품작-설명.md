# PersonaFit — 바이브코딩 경진대회 출품작 설명

> **한 줄 슬로건**
> 출시 전 'AI 포커스 그룹' — 100만 한국인 합성 페르소나를 84ms에 전수 스캔해
> *누가·어디서·뭐라고·어떻게 팔지·A안 vs B안*까지 한 화면에.
> (단, 실제 전환율이 아닌 합성 기준 '타겟 적합도·반응 경향'입니다.)

# ① 내용 (작품 설명)

## PersonaFit — 출시 전, 시장을 먼저 데려오는 'AI 포커스 그룹'

> **정직성 원칙(전제):** 본 문서의 모든 분석 결과는 **합성(가상) 한국인 페르소나 기준**의 *'타겟 적합도와 반응 경향'* 을 정량화한 것이며, **실제 가입 확률·전환율이 아닙니다.** 합성 페르소나가 실제 한국인을 얼마나 닮았는지, 그리고 결과가 실제 전환율과 얼마나 상관되는지는 **별도 검증이 필요**합니다. 본 도구는 실제 설문·포커스그룹을 **대체하지 않으며**, 그 앞 단계에서 가설을 압축하는 사전 탐색 도구입니다.

### 1. 한 줄 정의
상품설명서·약관·마케팅 카피·신상품 컨셉(또는 TXT·PDF·DOCX·HWP·HWPX 파일)을 입력하면, **100만 명의 합성 한국인 페르소나**와 매칭해 *"누가 얼마나 반응할지 · 어느 지역을 공략할지 · 사람들이 뭐라고 말할지 · FP가 어떻게 팔지 · A안과 B안 중 뭐가 나은지"* 를 한 번에 산출하는 **상품 기획·마케팅 분석 도구**. 한마디로 **출시 전 'AI 포커스 그룹'** 입니다.

이 출품작의 두 축은 **(1) 도메인 제품 가치** 와 **(2) 바이브코딩(AI 페어코딩)으로 고난도 풀스택을 완주한 개발 서사** 입니다.

### 2. 대상 사용자
보험·금융 **상품 기획자**, **FP(보험설계사)**, **마케터**. 출시 의사결정과 영업 현장 사이의 거리를 좁히는 것이 목표입니다.

### 3. 8개 핵심 기능

| # | 기능 | 핵심 산출물 |
|---|------|-------------|
| ① | **상품 분석** (`/analyze`) | 반응 강도 카드(100만 중 핵심 반응층 인원·1순위 공략지역·평균점수), **점수 DNA 워터폴**(의미적합도+룰보너스+관심사+보험관심 분해), 타겟 인구통계 분포 + **baseline-lift**(전체 대비 과대표집 배수), 공략 지역 지도(Kakao), 1인칭 찬반·반대 의견, **숨은 세그먼트 발굴**(예: 40대×자영업×부산), AI 종합 리포트 |
| ② | **A/B 테스트** (`/abtest`) | 두 안을 같은 100만 명에게 동시 분석 → 비교표·겹침 벤다이어그램·카테고리 발산도·**스윙층 X-레이**·추천안·**분할운영 플레이북**·FP 판매전략 |
| ③ | **겹침 분석** (`/cannibal`) | 3개 이상 안의 반응층 자기잠식을 겹침행렬(Jaccard)·커버리지(greedy union)·노출분포·전용층으로 분석. 집합연산이라 **LLM 호출 0** |
| ④ | **페르소나 탐색** (`/personas`) | 자연어("40대 부모와 동거하는 자영업자") → 메타조건 자동 추출 + 시멘틱 검색 + 세그먼트 저장(설문 대상 재사용) |
| ⑤ | **가상 설문** (`/surveys`) | 4단계 마법사(기본→대상→질문[직접/Excel·Word 임포트/AI추천]→실행), 실시간 진행 모니터, 질문별 통계 차트, CSV 내보내기, AI 총평 |
| ⑥ | **What-if 실험실** | 타겟·관심사 가중치 슬라이더 → 100만 분포 즉시 재계산. 임베딩 캐시로 **임베딩 API 0콜**, 수십 ms 응답, 원본 대비 델타 표시 |
| ⑦ | **데이터 현황** (`/overview`) | 100만 행 데이터셋 대시보드(지도·인구통계·직업 Top·텍스트 샘플) |
| ⑧ | **이력·세그먼트 + 관리자** (`/admind`) | 전 분석 JSONL 영속화·재열람, LLM provider(OpenAI/sLLM/Anthropic)·모델 **런타임 전역 전환** |

부가: **SSE 스트리밍 분석**(소구점→점수→의견→리포트 단계별 실시간), **PII 마스킹**.

### 4. 데이터와 알고리즘

**데이터** — `nvidia/Nemotron-Personas-Korea` 100만 행, **CC BY 4.0(상업적 이용 가능)**. 페르소나 텍스트 7종(persona + 전문직/스포츠/예술/여행/요리/가정) + 인구통계(성별·연령·혼인·가구·학력·전공·직업) + 지역(17 시도, 252 시군구). NVIDIA NeMo Data Designer가 KOSIS·대법원·국민건강보험공단·KREI 통계를 기반으로 생성한 합성 데이터로, **전량 인메모리 적재**.

**스코어링 v3** — 단일 코사인 값이 아니라 4개 성분의 가산 결합입니다.
- **의미 적합도**: 코사인 유사도를 분석 내 z-score로 표준화
- **룰 보너스**: 연령·성별·가구·학력·직업 일치
- **관심사 친화도**: 6개 관심사 '개념 벡터'와의 코사인을 백분위 정규화
- **보험 관심**

가산 결합 후 **soft-ceiling**을 적용해 상위권이 100점에 몰리는 천장 포화를 해소(v1→v3 반복 개선)했습니다. 코호트 컷: 핵심 반응층 ≥81 / 타겟층 ≥73 / 관심층 ≥68. 점수가 어떤 성분으로 만들어졌는지는 **점수 DNA 워터폴**로 분해해 보여 줍니다 — 블랙박스가 아닌 설명 가능한 스코어입니다.

**검색** — 100만 행 **전수 코사인(full brute-force) ~84ms**.

| 항목 | 값 |
|------|-----|
| 대상 행 수 | 100만 |
| 검색 방식 | full brute-force cosine (ANN/HNSW 미사용) |
| 검색 지연 | 약 84ms |
| 적재 방식 | 전량 인메모리 |
| API 메모리 RSS | 약 13.5GB |

통상 대규모 벡터 검색은 HNSW 같은 근사 최근접 이웃(ANN)을 쓰지만, PersonaFit은 **의도적으로 ANN을 쓰지 않습니다.** 목적이 "상위 K명 찾기"가 아니라 **모집단 100만 전체의 분포 통계**(반응층 인원·지역 분포·baseline-lift·숨은 세그먼트)를 내는 것이고, 근사 검색은 분포를 왜곡하기 때문입니다. *표본 추정이 아닌 모집단 전수 통계* 라는 점이 분포·lift 수치의 신뢰 기반이자 이 작품의 아키텍처적 정체성입니다. (트레이드오프: 전량 인메모리·brute-force라 데이터가 더 커지면 메모리·지연이 선형 증가합니다.)

**임베딩** — KURE-v1(한국어 특화 로컬 GPU, 1024d) + 2계층 캐시(메모리 LRU + 디스크) → 외부 임베딩 API 비용 0, 캐시 hit <1ms.

### 5. 모델이 믿을 만한가 — Known-target 백테스트

정답 타겟이 명시된 보험 약관 11종(여성전용·시니어·유자녀·청년·고학력전문직·미혼1인·은퇴자·남성전용·현역군인·제주도한정·간호사)을 입력해, 상위 20명 분포가 명시 조건과 일치하는지 **자동 측정**합니다.

- **결과: 케이스 통과 11/11(100%), 체크 통과 22/22(100%)**
- 임베딩의 일반화 능력을 보여준 사례:
  - **현역군인** — 스키마에 군복무 필드가 없는데도 직업("병사/장교") 부분매칭으로 95% 남성·현역 관련 60% 매칭
  - **제주도한정** — 인구 1.4% 지역인데 상위 20명 중 50%(약 36배 over-representation) — 임베딩이 '감귤·해녀' 키워드로 간접 매칭

> 백테스트가 측정하는 것은 **"명시 타겟을 정확히 회수하는가"(타겟 회수 정합성)** 이지, 실제 시장 전환율 예측력이 아닙니다. 11/11은 합성 데이터 내부 정합성의 근거이며, 실제 전환율과의 상관은 별도 검증 대상입니다.

### 6. 바이브코딩(AI 페어코딩)으로 어떻게 만들었나

이 제품은 **AI 코딩 에이전트(Claude Code 등)와의 페어코딩**으로 프론트엔드 + 백엔드 + 데이터 파이프라인 + 모델 검증 + 라이브 배포까지 **풀스택 5개 레이어를 한 흐름으로** 구현한 결과입니다. 단순 CRUD가 아니라, 기술 심사 관점에서 의미 있는 난도 높은 요소를 AI 협업으로 완성했습니다.

| 난도 높은 구현 | 난도 포인트 | 달성 결과 |
|----------------|------------|-----------|
| 100만 행 인메모리 실시간 검색 | 표본 아닌 모집단 전수 통계 필요 → ANN 대신 brute-force | 100만 행 코사인 **~84ms** |
| 멀티 LLM provider 추상화 | OpenAI/sLLM(vLLM)/Anthropic을 단일 인터페이스로 묶어 런타임 전역 전환 | 관리자 페이지에서 코드 재배포 없이 교체 |
| 임베딩 모델 마이그레이션 | OpenAI 1536d → 한국어 특화 KURE 1024d + 품질 정량 측정 | self-retrieval median rank **152→4**, Recall@10 **0.14→0.63** |
| 스코어링 v1→v3 반복 개선 | 상위권 100점 천장 포화 해소 | soft-ceiling 도입으로 변별력 회복 |
| Known-target 백테스트 자동화 | 약관 11종 상위 20명 분포 일치도 자동 측정 | 케이스 11/11, 체크 22/22 통과 |
| SSE 스트리밍 + PII 마스킹 | 소구점→점수→의견→리포트 단계별 실시간 전송 | 분석 진행 단계별 실시간 확인 |

**협업 루프(재현 가능한 작업 방식):**
```
계획 → 구현 → 자동 검증(verifier) → 보안 리뷰 → 빌드 수정 루프
   → 적대적 자기검증(내 코드는 틀렸다 가정하고 반증 설계)
   → 에러패턴 메모리 축적(lessons)
```
사람은 방향·판단·도메인 정합성을, AI는 탐색·구현·검증을 분담했습니다. 핵심은 AI에게 "코드를 짜라"가 아니라 **"이 가설을 검증 가능한 성공 기준으로 바꿔 구현·측정하라"** 고 위임한 점이며, 검증 자동화와 메모리 축적이 결합되어 세션이 바뀌어도 같은 실수를 반복하지 않는 재현성을 확보했습니다.

### 7. 기술 스택

# ② 활용방안 — 누가, 언제, 어떻게 쓰나

### 시나리오 A. 상품 기획자 — 신상품 컨셉 사전 스크리닝
- **상황**: 신규 보험 컨셉 3안을 두고 어디에 개발 리소스를 투입할지 결정해야 함.
- **흐름**: `/analyze`에 각 컨셉(또는 약관 초안 PDF/HWP)을 입력 → **반응 강도 카드**로 핵심 반응층 규모·1순위 공략지역·평균점수 확인 → **점수 DNA 워터폴**로 "이 점수가 의미적합 때문인지, 인구통계 룰 때문인지" 근거 추적 → **baseline-lift**로 전체 대비 과대표집 배수 확인 → **숨은 세그먼트 발굴**로 기획 단계에 안 보이던 교차그룹(예: 40대×자영업×부산) 포착 → 3안이면 `/cannibal`로 반응층이 겹치는지(자기잠식) 점검해 라인업 중복 제거.
- **결과물**: 컨셉별 타겟 적합도·지역 우선순위·자기잠식 리포트. 비싼 시장조사 외주 전에 **내부에서 1차 거름망**을 돌림.

### 시나리오 B. 마케터 — 카피 A안 vs B안 출고 전 의사결정
- **상황**: 같은 상품의 마케팅 카피 A안·B안 중 무엇을 메인으로 걸지 결정.
- **흐름**: `/abtest`에 A/B 입력 → **같은 100만 명에게 동시 분석** → 비교표·**겹침 벤다이어그램**(A만/공통/B만)·카테고리 발산도·**스윙층 X-레이**로 "어떤 층이 A↔B 사이에서 흔들리는지" 확인 → **분할운영 플레이북**으로 "A로 갈지, B로 갈지, 층을 나눠 둘 다 운영할지" 추천 + FP 판매전략 수령.
- **결과물**: 출고 카피 방향 결정 + 분할 타겟팅 전략. 의사결정 회의에 그대로 올릴 수 있는 비교 자료.

### 시나리오 C. FP(설계사) — 고객 상담 전 무기 준비
- **상황**: 특정 상품을 어떤 고객에게, 어떤 화법으로 권할지 막막함.
- **흐름**: `/analyze`의 페르소나 **1인칭 찬반·반대 의견**으로 고객이 할 법한 우려(반대 의견)를 미리 학습 → A/B의 **FP 판매전략·분할운영 플레이북**으로 층별 소구 포인트와 예상 반론 대응 확보.
- **결과물**: 상담 스크립트 초안 + 예상 반론 대응 시나리오. 신입 FP 온보딩 보조 자료.

### 시나리오 D. 리서처/누구나 — 가상 설문으로 빠른 예행연습
- **상황**: 실제 설문/포커스그룹은 비용·시간이 크고, 출시 일정이 촉박함.
- **흐름**: `/personas`에서 자연어로 대상층을 찾아 **세그먼트 저장** → `/surveys` 4단계 마법사로 질문 작성(직접/Excel·Word 임포트/AI추천) → 실행 → 실시간 진행 모니터로 응답 누적 관찰 → 질문별 통계 차트·AI 총평·CSV 내보내기.
- **결과물**: 설문 문항·가설을 사전 점검. 단, **실제 설문의 대체가 아니라 가설 압축·문항 사전점검용**(정직성 원칙).

### 시나리오 E. 전략 담당 — What-if 실험실로 즉석 시뮬레이션
- **상황**: "타겟을 40대로 좁히면? 여행 관심사 비중을 높이면?" 같은 질문이 회의 중 쏟아짐.
- **흐름**: 슬라이더 조정 → **임베딩 API 0콜·수십 ms**로 100만 분포 즉시 재계산 → 원본 대비 델타 확인.
- **결과물**: 회의 중 실시간 시나리오 비교. 재분석 대기 없이 의사결정 속도 향상.

### 시나리오 F. 운영자/관리자 — provider 전환과 이력 거버넌스
- `/admind`에서 LLM provider(OpenAI/sLLM/Anthropic)·모델을 **런타임 전역 전환** → 비용·보안(사내망 sLLM)·가용성 정책에 맞춰 즉시 스위치. 백엔드 인터넷 비노출 + PII 마스킹 적용. 모든 분석은 JSONL로 영속화되어 의사결정 이력을 재열람·감사 가능.

### 시나리오 G. 심사·발표 관점 — "바이브코딩 역량 증명"으로서의 시연
- 100만 행 실시간 검색·멀티 LLM 추상화·임베딩 마이그레이션 같은 비-CRUD 난제를 AI 협업으로 완성한 과정을, 협업 루프(계획→구현→검증→보안→빌드수정→자기검증→메모리)와 함께 시연.
- 임베딩 교체 전후 검색 품질(rank 152→4), 스코어링 v1→v3, 백테스트 11/11처럼 **모든 의사결정이 측정 가능한 근거로 뒷받침**됨을 라이브로 증명.

# ③ 기대효과

> **정직성 원칙:** 아래 효과는 합성 페르소나 기반 '타겟 적합도·반응 경향' 분석이 가져오는 **워크플로우 개선**이며, 실제 가입 전환율의 상승을 보장하지 않습니다. 업무 효과는 "실제 매출 증가"가 아니라 **"리서치 우선순위 정렬과 의사결정 속도 향상"** 으로 한정합니다. 합성↔실제 상관은 별도 검증 대상입니다.

### 1. 제품 관점 — 정량 효과

| 항목 | 수치(팩트) | 의미 |
|------|-----------|------|
| 분석 1건 전체 | **19~25초** (소구점 추출 7~9초 + 100만행 검색 84ms + 리포트 11~12초) | 약관/컨셉 입력 → 종합 리포트까지 |
| 100만 행 검색 | 약 **84ms** | 모집단 전수 통계를 실시간으로 |
| What-if 재점수 | 수십 ms (임베딩 API 0콜) | 가정 변경 즉시 반영 |
| 임베딩 캐시 hit | <1ms | 반복 분석 가속 |
| 외부 임베딩 API 비용 | **0** | 로컬 KURE GPU 임베딩, 캐시 hit 시 추가 비용 0 |
| 검색 품질 향상 | self-retrieval median rank 152→4, Recall@10 0.14→0.63 | KURE 마이그레이션 효과 |
| 백테스트 | 11/11 케이스·22/22 체크 통과(100%) | Known-target 타겟 회수 정합성 자동 검증 |
| API 메모리 RSS | 약 13.5GB | 100만 행 전량 인메모리 |

기존에 설문 설계→모집→집계로 며칠~몇 주 걸리던 '시장 반응 가설 점검'을, 출시 전 사전 스크리닝 단계에서 **초~분 단위**로 반복 실행할 수 있습니다. A/B·자기잠식·가상설문까지 한 도구에서 끝나 도구 간 이동 비용도 줄어듭니다.

### 2. 비용 구조 — 외부 임베딩 API 0, LLM만 과금
- **임베딩 비용 0**(로컬 KURE), 캐시 hit 시 추가 비용 0. 겹침 분석(`/cannibal`)은 집합연산이라 **LLM 호출 0콜**.
- LLM은 선택 provider만 과금. 외부 DB 없음(JSONL/파일 영속화)으로 인프라 단순.
- 외부 의존(DB·임베딩 API)을 줄여 **반복 실험의 한계비용과 마찰을 크게 낮춤** → 기획자가 부담 없이 여러 안을 돌려볼 수 있는 환경. (단, 로컬 GPU·메모리 자원은 소요되므로 "무한 무료"는 아닙니다.)

### 3. 의사결정 품질 — 근거 추적 + 모집단 전수
- **점수 DNA 워터폴**로 "왜 이 점수인가"(의미적합/룰/관심사/보험관심 분해)를 추적 → 블랙박스 회피, 회의 설득력 확보.
- **baseline-lift**로 "전체 대비 몇 배 과대표집"을 정량화 → 직관이 아닌 과대표집 배수로 타겟 우선순위 결정.
- 표본 근사가 아닌 **100만 모집단 전수 통계**(brute-force) → 희소 세그먼트·지역 편중도 누락 없이 포착(숨은 교차그룹 발굴 포함).

### 4. 리스크 관리 — 자기잠식·반대의견 사전 점검
- `/cannibal`로 신상품이 기존 라인업·다른 안의 반응층을 자기잠식하는지 출시 전 점검.
- 페르소나 **반대 의견 패널**로 부정 반응·예상 반론을 미리 수집 → 카피·약관 표현 리스크를 사전 검토할 단서 확보.
- A/B **분할운영 플레이북**으로 "전부 한 안에 베팅" 대신 층별 분할 운영 옵션 확보.

### 5. 바이브코딩 관점 — 개발 생산성·완성도·재현성 (이 작품의 핵심 메시지)

| 항목 | 근거(팩트) | 의미 |
|------|-----------|------|
| 풀스택 완주 | 프론트(Next.js)+백(FastAPI)+데이터 파이프라인+모델 검증+라이브 배포 | AI 페어코딩으로 5개 레이어를 한 흐름으로 완성 |
| 비-CRUD 난제 해결 | 100만 행 검색 84ms, 멀티 LLM 런타임 전환, 임베딩 마이그레이션 | "단순 앱"이 아닌 고난도 시스템을 AI 협업으로 구현 |
| 측정 기반 의사결정 | 임베딩 교체 후 rank 152→4·Recall@10 0.14→0.63, 백테스트 11/11·22/22 | 감이 아닌 자동 검증으로 품질을 끌어올림 |
| 재현성 | 검증 자동화 + 에러패턴 메모리 축적 | 세션이 바뀌어도 같은 실수를 반복하지 않는 작업 체계 |

"AI가 빠르게 짜면 품질이 깨진다"는 통념에 대한 반례 — **검증 루프와 메모리 축적이 결합될 때 바이브코딩이 운영 가능한 완성도(라이브 서비스 https://persona.smap.site)에 도달**할 수 있음을 보여줍니다.

> 개발 기간 단축률·팀 생산성 배수 등 정량 수치는 사실 근거가 없어 **[개발 기간]·[팀 구성]** 확정 후 산출 가능합니다.

# ④ 기존 방식 대비 차별점·경쟁력

### A. vs 실제 설문 / 포커스그룹 / 외주 리서치 (제품 차원)

| 축 | 기존(실제 설문·포커스그룹·외주) | PersonaFit |
|----|-------------------------------|------------|
| **소요 시간** | 설계→모집→진행→집계로 수일~수주 | 1건 분석 **19~25초**, What-if 재점수 **수십 ms** |
| **표본 규모** | 수십~수백 명 표본의 근사 | **100만 명 모집단 전수**(brute-force 코사인 ~84ms) → 희소층·지역 편중 누락 적음 |
| **건당 한계비용** | 패널 모집·진행비·외주비로 높음 → 반복 실험 부담 | 외부 임베딩 API 0원, LLM만 과금·캐시 hit 시 0, 겹침분석 LLM 0콜 → 여러 안 반복 실험 용이 |
| **반복성·재현성** | 매번 새 패널, 조건 통제 어려움 | 같은 100만 명에게 **A/B 동시 분석**, 3안+ 자기잠식까지, What-if로 조건만 바꿔 즉시 재현 |
| **데이터 라이선스** | 사안별 계약 | **CC BY 4.0(상업적 이용 가능)** 공개 데이터 |
| **결과 형태** | 표본 추정치·텍스트 리포트 위주 | **모집단 분포 + baseline-lift + 점수 DNA 분해** + 1인칭 찬반·반대·지도 |
| **숨은 인사이트** | 설계한 질문 범위 안에서만 발견 | **숨은 세그먼트 발굴**로 의외의 교차그룹(40대×자영업×부산 등) 자동 포착 |
| **출시 리스크 점검** | 자기잠식·라인업 중복은 별도 분석 필요 | `/cannibal` 겹침행렬·커버리지·전용층으로 **자기잠식 내장 점검** |

**핵심 포지셔닝**: 핵심은 *"표본 추정"이 아니라 "모집단 전수 통계"* 라는 점입니다. 기존 리서치는 비용·시간 제약상 표본으로 모집단을 추정하지만, PersonaFit은 100만 행 전수를 brute-force로 스캔(84ms)해 지역·세그먼트 농도를 직접 셉니다. ANN/HNSW를 일부러 쓰지 않은 이유도 여기 있습니다 — 근사 검색은 분포를 왜곡하기 때문입니다. 다만 PersonaFit은 실제 사람 표본을 **대체하지 않습니다.** 합성 페르소나의 반응 경향이므로, 비싼 실제 조사 **앞 단계의 가설 좁히기·우선순위화**에서 가장 강력하며, 살아남은 안만 실제 검증으로 넘겨 **조사 ROI 자체를 높이는** 것이 차별점입니다.

### B. 기술적 차별점 (심사위원 관점)
- **한국어 특화 임베딩 마이그레이션을 정량 지표로 검증** — self-retrieval rank 152→4, Recall@10 0.14→0.63. 막연한 "성능 개선"이 아니라 재현 가능한 수치 근거.
- **자동 백테스트(Known-target)로 모델 정합성을 자가 측정** — 케이스 11/11·체크 22/22(100%). 군복무 필드가 없는데도 직업 부분매칭으로 현역군인을 잡고, 인구 1.4% 제주를 약 36배 과대표집으로 잡아내는 임베딩의 일반화 능력 검증.
- **멀티 LLM provider 추상화 + 런타임 전역 전환** — 단일 벤더 종속 없이 OpenAI/sLLM/Anthropic을 운영 중 스위칭.
- **비용·보안 동시 설계** — 외부 임베딩 API 0원 + 외부 DB 없음 + 백엔드 비노출(rewrites 프록시) + PII 마스킹.

### C. 다른 바이브코딩 출품작과의 차별점 (이 대회의 핵심)
1. **CRUD를 넘어선 난도** — 100만 행 인메모리 실시간 검색, 멀티 LLM 런타임 전환, 임베딩 모델 마이그레이션, 스코어링 v1→v3, 자동 백테스트. 보통의 폼·목록 앱과 차원이 다른 시스템을 AI 협업으로 완성.
2. **'측정 가능한 바이브코딩'** — AI가 코드만 짠 게 아니라 품질 개선을 수치로 증명(임베딩 rank 152→4, Recall@10 0.14→0.63, 백테스트 11/11). "예뻐 보인다"가 아니라 "더 좋아졌다"를 데이터로 말함.
3. **재현 가능한 협업 루프** — 계획→구현→자동 검증→보안 리뷰→빌드 수정→적대적 자기검증→에러패턴 메모리 축적. 일회성 운에 기대지 않고 세션 간 일관성을 확보한 작업 체계 자체가 차별점.
4. **정직성 내장** — 합성 기준임을 화면·리포트 전반에 명시하고 실제 전환율로 과장하지 않음. 바이브코딩의 속도가 신뢰성 표기와 결합된 보기 드문 사례.
